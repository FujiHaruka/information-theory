## 2. 効かなかった道具と効いた道具

⚠ **本 relay の固有性は「新しい道具を見つけたこと」ではない** — 親 plan §4.5 が前 relay の実測を受けて

⟹ 本節が書けるのは **規約化した結果どうだったか**だけである。

**規約の 3 道具** = (1) 恒等式への帰着 / (2) 適格性・最適性の分離構造を使った構造つき全探索 /
(3) 明示 witness の直接評価 (閉形の族 / 反例の手構成)。

**実測**:

- ⭐ **主要な判定はすべて (1) か (3) で出ている**。`ε` を厳密 0 に閉じた leg は恒等式 2 本 + 初等証明で
  出ており、**許容差・格子・分枝限定を 1 つも使っていない**。`UV = C` の gate も、`C` 側の下界を
  **全方向を埋める 1 パラメータ族の明示 witness** で与えて出している。

  前 relay で 6 度再現した最も高くついた誤りであり、⟹ **規約化は効いた**と言える範囲がここである。
- ⚠ **ただし「効いた」の射程は狭い** — 規約が禁じたのは**掃引を証拠に使うこと**であって、

⚠ **(1) と (3) は「値は機械・導出は我々」という混合の confidence を持つ**ので、facts の各行が


- **着手前 6 本立て型** (N10) — 見出し型だが本数が違い、⚠⚠ **1 本が `予想` タグで

  「機械で確認」で埋まっている** ⟹ **当たり外れの勘定に入らない行が混じる**。

  `評価不能` ではない**。

⟹ ⚠⚠ **2 欄を足しても 20 leg に届かない (監査 訂正 7 が機械で出した)** — **欄 (i) の 4 leg +

## 4. ⭐ 起票と実行を別エージェントに分け、git で凍結する作法 (r19–r22)

本 relay 後半の 4 leg (N15 / N16 / N17 / N18) は、**起票エージェントが見立てと反証条件を書いて commit し、
実行エージェントは §0 / §1 を 1 文字も書き換えず §2 以降だけを書く**という形で回した。
⚠ **効いた / 効かなかったは、機械で引けるものだけで書く**。

**機械で引けたこと**:

1. ⭐ **凍結は 4 leg とも守られた**。各 leg の敵対的独立監査が**独立に**凍結区間の md5 を取り直して
   確認しており、監査 md にその軸が立っている
   (`rg -n '凍結' docs/shannon/bc-t3c-n1[5-8]-audit.md`)。⟹ **4/4**。
2. ⭐⭐ **凍結の検査手順そのものは、著者ではなく監査が壊して直した**。
   r20 の監査が「**ブリーフと親 plan が指定した md5 比較コマンドは構造的に偽陽性を出す**」ことを
   実測で示し (末尾の空行 1 本で md5 が食い違う)、**空行を落として正規化する形**へ是正した。
   ⚠⚠ **その是正は以後の起票 md にそのまま焼き込まれ、r21 / r22 / 本 leg の起票文はすべて
   正規化つきの形を持っている**。⟹ **凍結の作法は 1 度壊れ、監査によって修復されて伝播した**。
3. ⭐ **偽陽性の逆 (偽 PASS) も名指しで塞がれた**。r21 の監査が「**範囲が非空であることを先に確認してから
   md5 を取る**」を実行しており、⚠ **範囲指定を誤ると空文字列どうしが一致して PASS する**という穴が
   明示的に閉じられている。
4. **反証条件の発火は leg ごとにばらけた** — 逐語は各 leg 成果物 §4。⚠⚠ **3 本のうち何本が発火したかを
   relay 全体で合計しない** (条件文の内容が leg ごとに違うので、合計に意味が無い)。
5. ⚠ **不発火の質が区別されるようになった** — r21 / r22 は「**無条件の不発火ではない**」を明記した形で
   書いており、⟹ **「不発火」を「問題なし」と読ませない粒度が入った**。
6. ⚠⚠ **それでも凍結の確認コマンドはまだ壊れている。本記録 leg で 2 度目の誤判定が出た** —
   今度は**偽陽性ではなく偽陰性**である。**起票 commit の側には終端の見出し (`## 2.`) が存在しない**ので、
   **同一のコマンドを両側へ当てると `sed '$d'` が §1 の最終行そのものを削り、md5 が食い違う**。
   ⟹ ⚠⚠ **「凍結が破られた」と読みうる出力が、中身が 1 文字も変わっていない状態で出る**。
   ⟹ ⭐ **正しい形は「両側で切り出しコマンドが変わる」ことである** (逐語は本 leg の成果物 §3.6)。
   ⚠ **r20 の是正 (空行の正規化) は依然として必要だが、それだけでは足りない**。
7. ⭐⭐ **⚠⚠ 「`git diff` の削除行 0」を md5 非依存の裏取りに使ってはならない (監査 訂正 9。⚠ 後続 relay 向け)** —
   本記録 leg は削除行 0 を「§0 / §1 は 1 文字も書き換えられていない」の独立な裏取りとして挙げたが、
   ⚠⚠ **削除行 0 は「書き換えられていない」を含意しない** — **凍結区間への挿入は削除行 0 のまま通る**。
   監査は**凍結区間の途中へ 1 行入れた版を実際に作り、当該テストが削除行 0 で PASS すること**を
   機械で実演した。⟹ ⭐ **md5 に依存しない正しい裏取りは次の 2 本である**:

   ```bash
   git diff <起票 commit> -- <md> | rg '^@@'     # hunk が末尾 1 個の append だけであること
   git show <起票 commit>:<md> > /tmp/frozen.md  # 起票側の全行 (= N 行)
   head -N <md> > /tmp/cur.md && cmp /tmp/frozen.md /tmp/cur.md   # byte 一致
   ```

   ⚠ **本 leg の凍結そのものは監査が上の 2 本で独立に確定させており、結論は動かない** —
   ⚠⚠ **不足していたのは論法だけである**。⟹ **凍結検査を道具化するときは、削除行の数え上げではなく
   hunk 位置と byte 比較を実装すること** (§8 の新規提案 3 本目に反映済)。

**⚠ 機械で引けなかったこと** (→ §5 の未確認へ送る):

- ⚠⚠ **「起票と実行を分けたから見立てが当てにいく形にならなかった」は測れていない**。
  測れたのは**凍結が破られなかったこと**だけで、**分けなかった場合との比較は存在しない**。
  ⟹ ⚠ **作法の効果を主張しない**。
