既存の proof-log は Lean 形式化のボトルネック分析だが、**本件は探索プロセスのボトルネック分析**である
(層 3 = 形式化は意図的にスコープ外。親 plan §2.1)。成果物は散文の候補経路 + 数値 probe + 確定事実の
台帳で、将来「未解決問題に長期 relay で挑むとき、どこで時間が溶けるか」を自動検出するための

## 1. 問題のキャラクター

支配項は **新規性判定と「その測定値が何を測ったか」の管理**であって、証明そのものではなかった。
証明できた命題はどれも安い。(H1) / (H3) / (H4) / (H6) は `prove_identity` による**係数相殺**、
(H5) は既知不等式の連鎖、閉包補題は 4 行である (facts §L13 / §L15 / §L16 / §L17 / §L18)。
一方、経路を 1 本も生まなかった leg の死因を並べると全部が別系統の判定ミスに帰着する:

| leg | 何が起きたか | 死因の型 |
|---|---|---|
| L0 | F3 が REFUTED (UV は最良既知 outer ではない) ⟹ 軸 B の第一手が文献に先取りされていた | 文献の読み違え |
| L3 | 差し替え先が元クラスと**同値** (両方向 `machine`) | 対象の自由度の数え落とし |
| L8 | R1 の 12 step すべてに逐語出典が付いた | 二次文献だけで `new` と読んだ |
| L12 | 軸 A の残り 2 本とも `known-result` で着手前に決着 | 同上 |
| L13 | 記録済の必要条件 (N1)(N2) を**両方通した**候補が generic に死んだ | 必要条件が退化点に張り付く |
| L17 | 前 leg が渡した「詰めどころは `Λ_split` 側」が同一 run の測定で逆と判明 | 非論理的な推論の伝播 |

⟹ **「解けない」で止まった leg は 1 つも無い**。止めたのは毎回「既に在った」か「測った量が違った」
のどちらかである。Lean 側の proof-log が「Mathlib に何があるか」の配線で溶けたのと同じ位置に、
本件では「**文献に何があるか**」と「**この数値はどの run の何か**」が座っている。

## 2. 歩留まりの実測

**組み替え前 10 leg (L0–L9) で経路 0 本、組み替え後 9 leg (L10–L18) で 3 本**。

- L0–L9 は文献 / probe 基盤 / 定義照合 / 軸 A・B・E・G の第一手 / 棚卸し 2 回で **経路 0 本**
  (R1 は L7 で立ったが L8 の gate で落ちた)。
- **L9 の組み替え (gate-first)** — 配分を **[探索 + gate] → [構築 + probe] の 2 leg 1 組**にした
  (親 plan §6.2)。理由は「gate のコスト (一次文献の取得) は構築 1 leg より安いのに、落ちるときは
  経路を丸ごと落とす」。
- L10–L18 は L10 (R2) / L15 (R3) / L16 (R4) が各 **1 leg で探索 + gate + 構築 + probe の 4 段**を
  通した。L12 は gate が候補を殺して 0 本 (構築枠は未消費)、L13 は構築枠を使って 0 本、L17 / L18 は
  事前登録どおり経路を増やさず鋭さと資格を撃った ⟹ **探索/構築 6 leg で経路 3 本** (親 plan §7)。

**死んだ経路 R1 のコスト = 2 leg** (L7 構築 12 step + L8 gate)。⚠ **ただし全損ではない** — R1 は
「軸 E のどこが開いているかを逐語出典つきで確定させた**地図**」として routes.md に残り (L19 で
1018 → 858 行に圧縮)、副産物として検算スクリプト `bc-route-r1-check.py` / **骨格の訂正**
(`{a_x}` と `θ` の間に Legendre 変換は存在しない、判断ログ 18) / `r1-step6-tightness` の取り下げ /
facts §L8 の 7 行 / 軸 E に残る唯一の口 ([AGN19] Lemma 2 の独立再現) を残した。**そして gate-first の
組み替えを駆動したのは R1 の死そのもの** ⟹ 2 leg の損失は以後 9 leg の配分を変えた入力として
回収されている。

## 3. 繰り返し出た失敗形 ← 次の relay への一番の入力

**同じ形で複数回起きたものだけを挙げる**。各項に「いつ・何が起きたか」を 1 例ずつ付ける。

### 3-1. 再導出できない数値を散文にキャッシュする

**現物**: L18 が観測した「rng 共有による見かけ上の損失」を、親 plan 判断ログ 32 (c) は `44%`、
facts §L18 は `40%` と**2 通りに書いていた**。L19 が決着させようとしたところ、**修正前のコードが
コミットされていない**のでログを引き直せず、バグを統制した形で再現して測り直しても
`44%` / `40%` に一致する量はどの実行にも現れなかった ⟹ **両方とも不採用** (facts §L19)。

**構造**: 判定は「偽であった」ではなく「**再導出できないので採用しない**」に留まる — 真偽すら永久に
確定しない。CLAUDE.md の「settled facts を散文にキャッシュしない」が指すのはまさにこの形で、
**規律の主張だけが生き、その大きさの根拠が消えた**。

### 3-2. run / インスタンス集合をまたいで数値を混ぜる

同じ形が**境界の取り方を変えて 3 回**出ている。

- **別 run・別量**: L17 が L16 の指示を検証するとき、L15 の dense slack 中央 `0.577` と L16 の
  `Λ_env` 残距離 `0.002655` は**別 run・別インスタンス集合かつ量も別** (slack と残距離) なので根拠に
  採れず、同一 run で測り直した (facts §L17 段 C)。
- **同一 run でも乱数の流れが別**: L18 で 2 つの族構築器が rng オブジェクトを共有して候補プールがずれ、
  **見かけ上の損失という偽の測定値**が出た (同じ種で seed し直して解消。判断ログ 32 (c)) ⟹
  「同一 run・同一インスタンス」は**乱数の流れまで含めて読む**。
- **`--quick` と full**: facts §L13 / §L16 / §L17 / §L18 が毎回冒頭で「数値はすべて全体実行のもの、
  `--quick` とは食い違う」と明記。L13 では P1 の最大違反幅が実際に食い違った。

### 3-3. 最適化器の非違反を証拠として過大に読む (偽陰性)

**現物**: facts §L13 の専用行 — **1 回の run の中だけで偽陰性が 3 件**出た。(a) 固定 `p` のチャネル
最大化が明示 witness 族の違反を 6 行中 3 行取り逃した (`d = 0.1` の行で最適化器 `0.376215` に対し
明示 witness 族 `0.410670`) / (b) dense 平滑化族の `ε = 1e-4` で 2 つの `p` の**両方**で最大化が
直接 witness に負けた / (c) P1 の class B が探索を強化しただけで **`0/40` → `18/40`** に変わった。
先例は §L10 の「ランダム再スタート 20 本が真の最大を `0.3058` bit 外した」で、合計 4 件目である。
**帰結 (規約化済)**: 掃引の非違反を「命題は生きている」と読まない / 決着は明示 witness 族の直接評価で
付ける / 統計は「率」ではなく「**探索強度に依存する下界**」と書く (routes.md 合流節 A の `0/140`)。

### 3-4. 「A 側で動かなかったから B 側が詰めどころ」という非論理的推論

**現物**: L16 が L17 へ渡した設計指示が「dense は `Λ_env` で動かなかったので詰めるなら `Λ_split` 側」
だった。L17 が**同一 run**で測ると残距離の中央は `Λ_split 0.522889` に対し `Λ_env 0.002955` で、
`Λ_split` 側のほうが**桁で緩い** ⟹ 指示は逆向きだった (判断ログ 31 (b) / facts §L17 段 C)。

**一般化**: `max` で結合した下界の鋭さを詰めるときは、**まずどちらの枝が `max` を取っているか
(`argmax` の分布) を測る**。改善幅ではなく枝の勝敗が結果を決める。実際 L17 は `Λ_cav` で
`Λ_split` を **−30%** 改善したのに `Λ_comb` の残距離は `0.002955` → `0.002955` で 1 桁も動かなかった。

### 3-5. 「安い証明」と「無価値な証明」の一致

**現物**: L18 は R4 step 5 の資格 (admissibility) を証明しにいき、まず「`{Z}` の閉包演算で作れる `W`」を
撃った。閉包性は**4 行で証明できた**が、その範囲の `W` は `Z` の劣化版から出られず**利得が定義から
ちょうど 0** ⟹ 出口条件はその範囲で完全に潰れる (facts §L18)。**一般化 (判断ログ 32 (b))**: **証明の
容易さと成果の価値が逆相関する構造**がある ⟹ **資格を証明しにいく前に「証明できる範囲に利得が
あるか」を先に測る**。本 leg は逆順で、閉包を潰してから「非劣化の base point が要る」に到達した。

### 3-6. 伝聞の確定事実をそのまま伝播させる (一次文献の誤同定)

**同じ形で 5 回**出ている。原因はいずれも「一次文献に当たる前に伝聞 (二次文献 / 前 leg の台帳行 /
引き継ぎメモ) の記述で判定し、その判定が下流へそのまま流れた」ことである。

- **L2 → L8**: L2 は「(a) `M` の閉凸性 / (b) 双対の段の**どちらの文献も供給していない**」と判定したが、
  L8 が原典 [AGN19] に**両方ある**ことを確定させた。原因は L2 が二次文献 [GLN25] しか読んでいなかったこと。
- **L7 → L8**: `r1-step6-tightness` を「開いた小問」として起票したが原典は `[·]₊` の切断で処理済。
  誤検出の原因は **[GLN25] が `[·]₊` を落として書いていること** = 同じ原因の 2 件目。
- **L15 → L17**: facts §L15 の「[GNA12] Eq. (2) が使うのは上凹包 `C[f(X)]`」は誤同定で、`C[f(X)]` は
  Conjecture 1 / 3 の側の道具だった ⟹ **L17 の kill-first に誤った事前確率を与えた**。
- **L16 → L18**: `bc-d2-lower-check.py` §3(b) の「`ε > 2δ` なら less noisy でない」は誤り (正しくは
  `ε > 4δ(1−δ)`、`2δ` は劣化の境界) ⟹ **利得の出る窓を 2 倍近く広く見せていた**。
- **L0 自身**: 着手時点のランドスケープにも同型の誤りが 3 件 (F2 の Marton 1979 単独帰属 / F6 の
  著者・年が F5 の論文との取り違え / F4 の `0.37111` は原論文が訂正した誤値)。

**規約化済**: §5-11 primary-source-first。⚠ ただし**規約が入った後の L15 → L17 / L16 → L18 でも
再発している** — §5-11 が定めるのは「`known` / `new` のラベルを**新たに付ける**前に一次文献を 1 本
取る」だけで、**既に台帳に載っている確定事実の再検証**を義務づけていないためである。

### 3-7. 記録済の必要条件を全部通しても generic に死ぬ

**現物**: L13 の候補 P1 / P2 は**(N1)(N2) をどちらも PASS していた**のに generic な反例で死んだ
(P1 は明示 witness の直接評価で margin `+0.062075`、class A の**全数 99/99** が違反)。原因は構造的で、
**記録済の必要条件は witness から抽出されるぶん、その witness が立つ*退化点*に張り付く** — ここでは
`|X| = 2` と決定論的 BC で、ちょうど kill 機構が相殺する 2 点だった (判断ログ 27)。**同型が 3 例目**:
P3 も「格子 BC 側だけを見て通した案 B と**同じ穴**」で (N1) で落ちている ⟹ §5-12 として規約化
(構築の前に generic な非退化インスタンス 1 本を当てる)。

### 3-8. 検索語 / フィルタの狭さで取りこぼす

- **L6**: 軸 B の不等号ステップは名前フィルタで 21 本と数えていたが、結論形で数え直すと **39 本**で
  **18 本を取りこぼしていた** (attacks `outer-slack-vs-thm7` 行)。
- **L12**: 一次文献の「一覧取得」を要約器に絞り込ませると**取りこぼしが沈黙する** (0 件と見落としが
  区別できない) ⟹ 全件を頁順で取ってから自分で絞る (判断ログ 25)。
- **§5-11 の実測 3 点**: ファイル名を推測せず一覧を 1 回取って `href` を抜く (推測 9 通りは全部 404 /
  `publications.html` は 200) / 会議版と掲載版があるなら掲載版を優先 / **表題語で探索を切ると標的を
  正面から扱う論文を落とす** (arXiv:1202.0898 は表題に濃度が出ない)。
- Lean 側 proof-log の「`rg` 0-hit を不在と読んだ」と**同じ形**である — 検索の盲点は言語 (Lean / 論文)
  を問わず**検索語が対象の呼び名に依存している**ことから来る。

## 4. 効いた道具

**探索速度を実際に上げたのは `bc_probe.py` の `prove_identity` (係数相殺 = 証明) であって掃引ではない。**

- **掃引 (`test_relation` / `maximize`) は「殺す」ためには効いたが「立てる」ためには一度も効いていない**。
  §3-3 の偽陰性 4 件が示すとおり、掃引の非違反は証拠にすらならない場合がある。
- 対して `prove_identity` は**残差ちょうど 0** を返した時点で証明である。この 1 機能が (H1) / (H3) /
  (H4) / (H6) / 利得の恒等式 / 閉包補題の中核を閉じた。特に **(H1) は問題そのものを書き換えた** —
  「鋭いチャネル依存スラックを作る」と「非負 4 項損失 `L'` を下から抑える」が**同じ問題**だと確定させ、
  以後の 3 経路すべての step 1 になった (facts §L13)。
- **明示 witness の直接評価** (最適化不使用) が確定値の階級として機能した — P1 の `+0.062075` /
  class A の `99/99` / P2 の `+0.037012` (facts §L13)。kill を担保したのはここである。
- **cell 証明書** (L18) が掃引と記号的証明の**間の第 3 の階級**を作った (単体を有限個の cell で被覆し
  各 cell を 1 本の不等式で閉じる ⟹ 残るリスクは浮動小数点だけ)。
- **符号の非対称性を先に決める** (§5-13) — `Γ` / `max_U` は最大化 = 真値の下界 ⟹ `Λ` は上振れ ⟹
  **正の deficit だけが証明書、負は最適化ノイズ**。同時に「`Λ` の推定が `L'` の推定を超えた行」を
  反例ではなく**推定不足**として分けて数える規律もここから出た (L15 / L16 / L17 / L18 の各節が全行印字)。
- **台帳の三分割** + **no empty leg** (§5-1) で確定事実ゼロの leg を 0 にし、**`killed` 行を削除しない**
  規約により死因が後続 leg の入力として再利用された (§5-9 の子 attack 起票)。

## 5. 計測基盤の穴 — 実測すると**塞がっていた**

⚠ 既存の proof-log ([kolmogorov-w2](proof-log-kolmogorov-w2-omega-noncomputable.md) 冒頭) は
「subagent へ dispatch した作業は親セッションの JSONL に残らず sidechain が 0 になる」と警告して
いる。本 relay は全 leg が subagent 中心なので同じ穴に当たると予想したが、**実測では当たらなかった**
— `session_metrics.ts` は subagent transcript を**別カラム**で集計しており、親の `Agent` 呼び出し件数と
subagent セッション数が一致する。⟹ **本 metrics は実作業量を表す** (比は metrics.md のサマリー表)。
既存 log の警告は当時の実測であって、現在は無効である。**残っている穴 3 つ**:

1. **L20 (本記録 leg) 自身が計上の途中にある** — 生成時点で進行中なので本 leg のターンは部分的にしか
   入らず、しかも本 leg の subagent が subagent 一覧に現れる = 自己言及的である。
2. **`--discover` は UTC、git のログは JST** で 9 時間ずれる ⟹ leg とセッションの対応を git 時刻から
   推定すると必ず 1 段ずれるので、`--turns` で touched files を照合するまで推定を確定と書かないこと
   (本 leg でも、事前の推定 12 本が relay の**設計セッション 1 本を取りこぼしていた**)。
3. **leg ↔ セッションは 1:1 ではない** — 1 セッションが 3 leg を含む場合 (r2 = L2+L3+L4) も、1 leg の
