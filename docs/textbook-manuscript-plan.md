## Approach

**既存 5 章の番号を動かして Cover–Thomas の順に差し込む**（ユーザー判断、2026-09-05）。
差し込みの結果、番号が動くのは既存 2 章だけで済む（第4章 通信路容量 → 第6章、第5章
最大エントロピー → 第10章）。第1〜3章は位置が変わらない。

順序は Cover–Thomas の章順を基本にし、**1 点だけ入れ替える**: 最大エントロピー（CT12）を
仮説検定と大偏差（CT11）の前に置く。理由は依存で、Chernoff / Hoeffding の形式化
（`Shannon/Chernoff/Basic.lean`, `Shannon/Hoeffding/*.lean`）が Csiszár 射影
（`Shannon/CsiszarProjection.lean`）を import しており、指数型分布族と Gibbs 形が先に要る。
CT 順のままだと §2 の前方参照違反になる。

章ごとの手順は 6 段で、1 章 = 1 サイクル。

1. **在庫**（オーケストレーター）— その章が紐付ける形式化済み宣言を洗う。`0 sorry` かつ
   `0 @residual` のものだけがポインタ先になる（原則 §7）。`scripts/sig_view.ts` と
   `rg` で宣言名・ファイル・結論の形を集め、章のブリーフに書く。
2. **草稿**（サブエージェント 1 体）— 節ファイルを書く。ブリーフに在庫・既出章の番号・
   基準実装（第1章）へのポインタを入れる。同時 1 体キャップを守る。
3. **機械検査**（オーケストレーター）— `build.mjs --audit-refs` の warn 0 件、
   `vocab.ts <章>` の原語混入 0 件まで直す。
4. **査読 1 周目** — `/textbook-review` の 4 観点。**サブエージェントは read-only の査読者も含めて同時 1 体まで**、1 体完了 → 次を発射の逐次で回す（2026-09-06 のユーザー指示。並列に回すと 5 時間制限に達する）→ 指摘を統合して修正。
5. **査読 2 周目** — 1 周目とは独立に、もう一度 4 観点を回す（1 周目の指摘リストは
   査読者に渡さない。渡すと独立性が失われる）→ 修正。
6. **公開とコミット** — `docs/textbook/site/deploy.sh` を回してコミット。
