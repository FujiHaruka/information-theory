## 2. Approach

**3 単位を「BC への依存度」で切り、依存の無い順に独立させる**。1 本の巨大な形式化として持つと、
中核 1–7 (BC を 1 つも含まない一般命題) の停滞が BC 側の受け皿まで巻き込む — それが親 relay で
形式化債務が可変枠を 14 leg 食った形の再演になる。切り分けの軸は 3 つ:

- **A は BC から独立** ⟹ 進度が B / C に伝播しない。Mathlib へ出せる形をしている。
- **B は既に型検査を通っている** ⟹ **type-check done まで最短**で、⭐ 親 §5.3 R4 の
  「アークが層 3 へ載せる def」の**受け皿にもなる** (親 §5 の N17 / N18 行)。
- **C だけが既存資産に触る** ⟹ 波及の実測を着手条件にする (§3.3)。

**依存関係**: `A ⟂ B` (独立、並行可) / `B → C` (C は B の def を消費する)。
⚠ **A → B の依存は無い** — B の閉性は古典側で閉じる (N2 §5.2 の B 行)。

**各単位は「gateway atom 1 本 → 通れば残りを起票 / 通らなければ `sorry` + `@residual` で退出」の形で
進める** (CLAUDE.md gateway-atom-first)。⚠ **単位まるごとを壁と宣言する前に、必ずその 1 本を機械に掛ける**。

## 5. 運用規約

- **退出路は 1 つだけ** — 詰まったら**署名は証明したい形のまま**残し、body を
  **`sorry` + `@residual(plan:bc-computable-region-formalization)`** にする (Definition of Done 2 段階:
  **type-check done** = 0 error でコミット可 / **proof done** = 0 sorry かつ 0 residual)。
  ⚠⚠ **hypothesis に証明の核を担わせて `sorry` を消すのは禁止** (`*Hypothesis` predicate へのバンドル、
  `:True` slot、退化定義の悪用、name laundering)。⚠ **`sorryAx`-free は必要条件であって十分条件では
  ない** — 完了判定には**署名走査**を併せる。
- **`def` / `Prop` の RHS に `sorry` が書けない場合**は、定義を書き直して核を別 `theorem` へ押し出す
  (CLAUDE.md「Mathlib-shape-driven Definitions」/「`sorry` が書けない場合の処理順」)。
- **Import Policy**: **`import Mathlib` を書かない**。必要なモジュールだけを足す。
  ⚠ 単位 A は **`import Mathlib.Data.Rat.Denumerable` の 1 行が必ず要る**
  (`import InformationTheory` の閉包に入っていない。facts N2-h)。
  新規ファイルを足したら `InformationTheory.lean` に `import` 行を追記する。
- **検証**: 内側ループは **`lake env lean <file>`** (無出力 = clean)。⚠ **`lake build` は検証に使わない** —
  大規模 refactor 後の一度きりの健全性確認だけに使う。上流の署名を変えた後に dependent が
