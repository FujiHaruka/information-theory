# leg 運用の改定 — 決着圧力を落とさずに理論構築を予算化する

> **対象**: `bc-open-problem-t3c-plan.md` の §2 / §4.5 / §5 / §5.1 / §6 と
> `bc-open-problem-attacks.md` の状態・死因語彙。
> **性質**: ⚠ **`GOAL-CHANGE` ではない** — §0 のゴールと完了条件は 1 文字も動かさない。
> 動かすのは **leg の進め方**だけである。ただし §0.1-3 (「書けない leg は起票しない」) の
> 運用形に触れるので、**適用にはユーザー承認を要する** (§8)。
> **Status**: 提案 (2026-08-07)。⚠ **未適用**。leg は停止中。

---

## 1. 診断 — 何が阻害されているか

前 2 relay (41 leg) + 本 relay (2 leg) を通じて、**新しい不変量・新しい領域概念・新しい証明機構を
導入した leg は 0 本**である。導入されたのは検証の道具 (N1 の DC 分枝限定) と局所的な構造定理
(M11 の適格性の凸構造) だけで、どちらも既存の定義の上での話に留まる。

これは能力の問題ではなく**設計の帰結**である。現行運用は 5 つの点で理論構築 leg を起票不能にしている。

| 規約 | 効いている圧力 |
|---|---|
| §4.5 「効く道具は 3 つだけ」 | 3 つとも**既存定義の上で命題を検証する**道具。新概念を導入する道具ではない |
| §0.1-3 「何を動かすか 1 行で書けない leg は起票しない」 | 理論構築は着手前に「何が動くか」を書けない ⟹ **起票できない** |
| gate-first (「GO/NO-GO どちらでも軸が 1 本確定するので最も安い」) | 決着可能な小問へ leg を流す装置。確定を返さない期間と非互換 |
| §6-4 配分カウンタ / 3 leg ゼロ進捗で park / no-progress×2 | 進捗が見えない期間を積極的に殺す |
| 死因語彙 5 語 (`numeric-counterexample` / `known-result` / `probe-failed` / `too-hard` / `mathlib-wall`) | 全部「既存命題を試して落ちた」形。**「道具がまだ無い」に当たる語が無い** (台帳自身が「語彙の穴」と認めている) |

⟹ **前 relay の未達を「配分では説明できない」と plan 自身が書いた次に疑うべきは、leg という
粒度そのものである**。そこはまだ疑われていない。

⚠ **ただし現行設計を否定しない** — 決着圧力は前 relay の失敗形 (最適化器の非違反を証拠と誤認する
形が 6 度再現) への正しい処方である。**外すのではなく、適用範囲を分ける**。

## 2. Approach

**決着圧力を落とすのではなく、成果物の型を増やして圧力の当たり先を変える。**

現行は成果物の型が 1 つ (判定 = GO / NO-GO / 未決) しかないため、「判定を返さない仕事」が
すべて「進捗ゼロ」に見える。型を 4 つに増やし、型ごとに別の検証基準を与えれば、
**理論構築 leg にも殺す基準が付く** ⟹ 不確実性を受け入れることと、規律を保つことが両立する。

骨子は 4 点:

1. **成果物の型を 4 つへ** (判定 / 定義 / 言い換え / 障害の構造) — §3
2. **アーク = 3 leg 1 単位の予算枠**。アーク内の個別 leg に決着を要求せず、**終端でのみ判定する** — §4
3. **進捗指標を「義務が減ったか」から「`bc-facts.md` の既存確定事実を何本再現するか」へ** — §5
   ⭐ **これが提案全体の要**。既存の台帳と検証器がそのままテストスイートになるので、
   探索枠のコストはゼロからの構築ではなく**既存資産の上への上乗せ**で済む
4. **層 3 (Lean) の使い方を「定理を載せる」から「定義を載せる」へ** — §6。
   形式化債務 (領域 def が 0 本) の解消と同じ方向を向く

## 3. 改定 R1 — 成果物の型を 4 つにする

| 型 | 成果物 | 合格条件 | 死因 |
|---|---|---|---|
| **判定** (現行のまま) | GO / NO-GO / 未決 | §4.5 の 3 道具のどれかで機械に掛かっている | 現行 5 語 |
| **⭐ 定義** (新設) | 新しい対象の def 1 本 + 健全性テスト | **facts の既存確定事実を N 本再現する** (§5) | `non-reproducing` (再現しない) / `inert` (どの既存判定にも接続しない) |
| **⭐ 言い換え** (新設) | 既存の問いを新語彙で書き直したもの + 元の問いとの同値証明 | 同値が §4.5 の道具で機械に掛かっている | `redundant` (既存語彙の単なる別名 = novelty gate 落ち) |
| **⭐ 障害の構造** (新設) | 「なぜ既存の道具では届かないか」を構造として書いたもの | 障害が**対象として名指しされ**、それを回避する条件が書かれている | `restatement` (「未決」の言い換えにすぎない) |

⚠ **「障害の構造」は「未決」と別物である** — 現行の「未決」は判定の不在を意味するだけだが、
この型は**届かなさそのものを対象化する**ことを要求する。M12 が特定した「`T_J` ごとに witness を
取り替える機構」は、現状「量化子の順序」としか呼ばれていない = **分離が起きる唯一の場所と
特定できているのに、その場所を記述する言語が無い**。これを埋めるのがこの型である。

⚠ **型は leg 単位ではなくアーク単位で宣言する** (§4)。

## 4. 改定 R2 — アーク (3 leg 1 単位) を導入する

**アーク** = 同一の対象について連続する 3 leg を 1 単位として予算化したもの。

- **アーク内の個別 leg には決着を要求しない**。§6-4 の配分カウンタ・「3 leg ゼロ進捗で park」・
  `no-progress×2` は**アーク内では引かない** (⚠ アークをまたいでは引く)。
- **アーク終端でのみ判定する**。判定は 3 択: `続行` (次アークへ、⚠ 連続 2 アークまで) /
  `park` (対象を退避、再開条件を明記) / `kill` (死因を §3 の語彙で書く)。
- **アークは起票時に 3 項目を書く** (§0.1-3 の代替、⚠ 「1 行で何を動かすか」は要求しない):

```
**アーク宣言 (A<n>)**: 型 = <定義 | 言い換え | 障害の構造> /
  対象 = <何を定義・言い換え・対象化しようとするか> /
  接続 = <facts のどの確定事実に接続するつもりか、節名で 3 本以上> /
  反証条件 = <どうなったらこのアークを捨てるか>
```

⚠ **`接続` を 3 本以上書けないアークは起票しない**。これが §0.1-3 の精神
(「書けない leg は起票しない」) を保つ点であり、**同時に決着の要求を外す点**である。
⚠ **`反証条件` を先に書く**のは §4.4-2 (緩める方向の見立ては殺し方を先に決める) の継承である。

## 5. 改定 R3 — ⭐ 進捗指標を差し替える

**現行**: 進捗 = 義務が減った / 反例が出た / 判定が付いた。
**改定**: 探索枠の進捗 = **`bc-facts.md` の既存確定事実を何本再現・統一するか**。

理由と実現可能性:

- `bc-facts.md` は L0–L19 / M1–M19 / N1 の確定事実を **claim 行 + 再検証コマンド + confidence** 付きで
  持っている ⟹ **そのままテストスイートになる**。新しい定義の健全性は「その定義の上で既存の
  claim を再導出できるか」で機械的に測れる。
- scratchpad の検証器 5 系統 (とくに Thm7 側を完備した独立実装) が既にある ⟹ 新しい対象を
  数値で評価する土台がある。**探索枠はゼロからの構築ではなく既存検証器の上への上乗せ**である。
- ⚠ **殺す基準がここから出る** — 再現本数が閾値未満の定義は `non-reproducing` で死ぬ。
  どの既存 claim にも接続しない定義は `inert` で死ぬ。**不確実性を受け入れることと、
  規律を保つことがここで両立する**。

**閾値の初期値** (⚠ 実測が無いので暫定。最初のアーク終端で較正し直す):

| アーク終端の再現本数 | 判定 |
|---|---|
| 0 本 | `kill` (`inert`) |
| 1–2 本 | `park` (再開条件 = 接続先を 3 本に増やせたら) |
| 3 本以上 | `続行` |
| ⭐ 既存の**独立な** claim 2 本以上を**同一の機構で**説明した | `続行` + 判定枠へ昇格を検討 |

⚠ **「再現」は逐語一致ではなく値レベル一致でよい** (M9 が「対角 witness の読み」で確立した
基準と同じ)。⚠ **再現の確認は §4.5 の 3 道具で行う** — 道具立ては変えない。変えるのは
**何を検証するか**だけである。

## 6. 改定 R4 — 層 3 の使い方を変える

**現行**: 層 3 = 散文で立った定理を Lean へ載せる。
**改定**: 探索枠のアークでは **定義を Lean へ載せる**ことを成果物に含める。

- 新しい対象の `def` は**証明が要らない** ⟹ 散文が決着していなくても載る。
- **Lean に書けること自体が健全性テストになる** (型が付く / 既存の in-project 資産と接続する)。
- ⭐ **形式化債務と同じ方向を向く** — 在庫が確定させたとおり「領域としての `Thm7` は Lean に 0 本」
  「in-project の領域 def 11 本は実効コンパクト性の証拠を 1 つも運ばない」。
  探索枠で置く定義は、この 0 本を埋める側に直接効く。
- ⚠ **`sorry` + `@residual(plan:…)` の退出路はそのまま**。定義に付随する性質が示せないときは
  honest に `sorry` で置く (CLAUDE.md「Mathlib-shape-driven Definitions」の第一選択)。

⚠ **現行の枠構造 (可変枠 14 / 形式化 3 / 記録 1) は配分事故を防ぐことに成功している** ⟹
**枠の存在は残し、可変枠の内訳を割る**。

| 枠 | leg | 現行との差 |
|---|---|---|
| **探索アーク 2 本** (A1 / A2、各 3 leg) | **6** | ⭐ **新設**。可変枠 14 から出す。決着を要求しない |

| 棚卸し | (内数) | ⭐ **アーク終端と同じ leg に置かない** (自己採点になる) |

| **未配分** | **1** | ⭐ **新設**。アーク 1 本目の結果を見てから配る |

アーク 1 本目の産物が判定枠で使えるかを見る。

## 10. 引き受けるリスク (⚠ 正直に書く)

- **探索アーク 6 leg が何も返さない可能性は実在する**。⚠ **それは失敗ではなく引き受けた賭けである**
  と先に書いておく — 現行設計で 41 leg 使って未達という実績があるので、**期待値の比較としては
  悪くない**が、⚠ **良いと断言する根拠も無い** (アーク運用の実測が 0 だから)。
- **`redundant` で死ぬ公算が高い** — 新しい語彙が既存の言い換えにすぎないケースは、
  この分野では普通に起きる (L8 が R1 に対して実測した形)。⟹ **novelty gate をアーク終端ではなく
  1 leg 目に当てる**。
- **アークが「決着しない言い訳」に劣化する危険** — 処方は §5 の再現本数 1 本のみ。
  ⚠ **prose の印象で判定しない**。⚠ **アーク終端の判定は棚卸し leg と同じ leg に置かない**。
- ⚠ **本改定は §0 のゴールへの到達確率を上げると主張していない**。主張しているのは
  **「思いつく場所に leg が入っていない」という現状を解消する**ことだけである。
