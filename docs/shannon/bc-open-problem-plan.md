## 2. Approach

**三層 × 階段 × 台帳**。

### 2.1 三層 — ただし**この relay のゴールは層 1〜2 まで**

```
層 1  散文        アイデア + 証明スケッチ (自然言語 + 数式)        ← 本 relay のゴール
層 2  proof-probe 核 1〜2 ステップだけを機械検証 (数値 sim or Lean)  ← 本 relay の検証手段
層 3  形式化      散文全体を Lean へ                              ← ⚠ 本 relay のスコープ外
```

**層 3 は次の relay に回す**。**散文レベルの証明がまだ存在しない**以上、形式化は前提を欠く。本 relay の
成果は「**probe を通過した候補経路が数本**」で、それらが**誤っている可能性は織り込む** (誤りの排除は
層 3 の仕事)。**層 2 の役割もそれに合わせて変わる** — 形式化への入口ではなく、**散文の自己欺瞞を最短で
殺す装置**。「散文で証明できた気がする」を 1 leg 以内に潰せるかが探索速度をそのまま決める。

層 2 の 2 形態と使い分け:

- **数値 probe (主力)** — 命題を有限アルファベットの数値最適化に落として反例を探す。**基盤は
  [`bc_probe.py`](bc_probe.py)** (自己検証 = `python3 docs/shannon/bc_probe.py`、API と使用例は同ファイルの
  docstring が SoT)。載せ方の要点 3 つ: **線形情報量式** → まず `prove_identity` で**係数相殺 = 証明**を
  試み、落ちたら `test_relation` で掃引 (**掃引の成立は証拠、係数相殺は証明** — 台帳で書き分ける) /
  **構造制約** → `BayesNet` に DAG として置く (⚠ 一般 BC は `Y ⊥ Z ∣ X` を仮定できないので `(Y,Z)` は
  **結合 1 ノード**にする) / **補助変数上の最大化** → `maximize` が返すのは最良値であって最大値の証明では
  ない (⚠ **ランダム方向の摂動だけで「局所最大だ」と結論しない** — 改善方向が単体の**境界**にありランダム
  20,000 方向が全滅した実例。`directions=` に境界点を明示的に渡す)。実行可能な probe は `bc-*-check.py` に
  置き本 module を import する。**sim は必ず Lean の `def` と逐語照合してから信用する** — 照合義務は
  **その `def` を扱う consumer 側の probe が負う** (基盤側は entropy の規約 1 点のみで、これは済)。
- **Lean probe (安いときだけ)** — **既存資産への問い合わせで済む場合に限る** (典型は仮説差し替えの
  再コンパイル)。新しい補題を積み始めたらそれは層 3 なので**打ち切って散文に戻る**。

### 2.2 階段 / 2.3 台帳

- **階段** — 未解決本体だけを目標にすると「解けない = 成果ゼロ」になり、それが諦めの最大の原因になる。
  **どこで止まっても成果が残る**よう独立に価値を持つ 4 段に割る (§3)。
- **台帳** — 試した attack は死んだものも全部残す。**死因の分類**まで書くのが要点で、「数値反例で死んだ」
  「既知だった」「単に難しい」は次の一手が全く違う (§5-4)。

## 3. ターゲットの階段

**完了条件はすべて散文ベース** (層 3 はスコープ外、§2.1)。

| 段 | 内容 | 完了条件 | 価値 |
|---|---|---|---|
| **T0** | ギャップの正確な固定 | 内界・外界・容量領域が同じ言語で並び、「何が未解決か」が曖昧語なしで書ける | 在庫でほぼ達成済 |
| **T1** | **既知の負の結果**の再現 | F4 (BSSC のギャップ) / F5 (NEG の suboptimality) の証明の**筋が追えていて、どの道具が効いたかが言える** | 道具立てがここで揃う。新規性は無いが、以後の全 attack の入力 |
| **T2** | **人類未知の中間結果の候補経路** ← 本命 | §4 の軸のいずれかで、§3.1 の 5 条件を満たす経路が立つ | 次 relay の形式化対象。ここが現実的な到達目標 |
| **T3** | 未解決本体の候補経路 | 一般 BC の計算可能な特徴付け (肯定 or 否定) について同じく経路が立つ | 30 年級。狙うが期待値は置かない |

### 3.1 「候補経路」と呼べるための 5 条件

**これを満たすものだけを経路 (route) として台帳に載せる**。満たさないものは `idea` 枠に置く (量産して
よい — 制約は昇格時だけ)。基準が無いと「経路が 5 本出た」が空虚な数字になる。

1. **主張が確定している** — 何を証明する経路なのかが 1 文で書け、その命題に曖昧語 (「適切な」
   「よい性質の」) が無い
2. **ステップが列挙されている** — 中間命題の列があり、各ステップの入力と出力が書かれている
3. **各ステップにラベルが付いている** — `known` (既知の道具で行ける、出典つき) / `new` (新規に証明が
   要る) / `gap` (未検討)。**`gap` が残っていてもよい** — 隠さずに書いてあることが条件
4. **殺されていない** — 主張自体の小ケースを数値 probe に 1 回は通した
5. **既知でない** — 文献確認を 1 回通した (§5-7)

### 3.2 経路の確信度ラベル

`probed` (核ステップが数値 or Lean で検証を通過した) / `unprobed` (散文のみ、probe 未実施) /
`refuted` (殺された。死因を台帳へ)。**`unprobed` のまま「証明できた」と書かない** — 誤りを織り込むこと
(§2.1) と、誤りを誤りと表示しないことは別。層 3 を捨てた代償はこのラベルで払う。

### 3.3 本 relay の到達目標 (L15 の収穫判定で使う)

- **最低ライン**: 5 条件を満たす経路 ≥ **2 本**、うち ≥ **1 本**が `probed`
- **目標**: 経路 ≥ **3 本**、うち ≥ **2 本**が `probed`
- 経路の本数は多いほど良いわけではない。**次 relay で形式化に着手できる粒度**まで書けているかが基準。
- **現在地 (L16 完了時点) = 有効な経路 3 本** (**R2** / **R3** / **R4**、いずれも `probed`) ⟹
  **目標 (3 本 / うち 2 本 `probed`) に到達**。R1 は (4) を通ったが (5) で不合格ゆえ数えない。
  ⚠ **本数の現物は台帳から再導出する** (routes.md の経路一覧が SoT。5 条件を満たすまで経路表に
  載らない。plan にキャッシュしない)。
  ⚠ **数え方に添える留保 3 つ** (§7 と同じもの。これを外して「3 本立った」と読まない):
  **(a) 3 本とも step 1 ((H1)) を共有する** / **(b) R4 は R3 の step 7 (`Λ_sup`) の強化でもあり、
  産物は同じ `Λ_comb` に合流する** (`Λ_comb := max{Λ_split, Λ_env}` へ更新) ので完全に独立な 3 本では
  ない / **(c) R4 の新規性は (H5) に局限される** (`Λ_env` という対象も構造的な読みも gate は既知側と
  判定した。facts §L16 の文献行)。⟹ 数えているのは「核の独立性 + 証明の有無」である。
- **⚠ 最低ラインの数値は動かしていない** (L9 / L13 / L14 / L15 とも)。出したのは**到達可能性の判定**で
  あって基準の改定ではない — 再判定と代替収穫物は §7。

## 4. 攻撃軸 — 未知の中間結果の候補

各軸に (a) 狙い / (b) 形式化プロジェクトゆえの優位 / (c) 最初の一手 / (d) 収穫ライン (死んだときに残るもの)
を書く。**単一の軸に賭けない** — §5-5 のラウンドロビン規約で強制的に回す。

### 軸 A — 在庫駆動の最弱仮説抽出 (**L12 で経路の供給源としては閉じた**)

- **決着 (L3 → L12)**: 第一手 FAIL (差し替え先は元クラスと**同値**、両方向 `machine`) → 子 2 本とも
  **`killed(known-result)`**。同値が破れるのは量化範囲を狭めたときだけで、それが [N10] の
  *sufficient class*、得られるクラス (ELN / EMC) は容量領域まで確定済 (facts A1–A3)。
  ⚠ **手順の訂正 (他軸へ流用するとき必須)**: 実使用の棚卸しは `rg` ではなく **`dep_graph.sh` の前方閉包**
  で行い、**辺の向き先が `def` 自身か名前つき補題か**を区別する (`exact hmc _` 形は `rg` から漏れる)。
- **(d) 収穫ライン**: 新クラス切り出しは達成不能と確定。代わりに **[N10] Theorem 2 = 我々の
  `bc_moreCapable_capacity_eq_uv` の真の一般化**が**形式化標的**として残る (層 3 = 次 relay)。加えて
  L3 の同値 (`machine`) と schema (**`∀p` 型のクラス述語は条件つき化で必ず潰れる** = 軸 A 系の起票を
  事前に殺すフィルタ)。
- **残った子 2 本は主語が別** — `eln-canonical-class` (ELN/EMC の membership から `∃P` を消せるか。鍵は
  **濃度上界** = 軸 F の主語) / `superposition-optimality-scope` (⚠ 根拠が二次文献 1 本なので §5-11)。
  近距離の開き口として `sum-bc-classes` (⚠ **積ではなく和**で軸 E の合成演算とは別物)。

### 軸 B — 外界の緩みの局所化 (**本 relay での実働は終了**)

- **L6 で決着 — 同定完了・帰結は否定的**: 旧狙い「UV の証明で捨てた項を拾う」は Gohari–Nair Theorem 7 が
  実行済 (F3) ゆえ標的を「我々の Lean 証明のどのステップが改善項に対応するか」へ差し替えた結果、ステップ
  は 21 ではなく **39 本** (matched 22 / no-slack 12 / unmatched 5) で `unmatched` 5 本は**いずれも最終
  領域を動かさない** ⟹ **我々固有の exploitable な緩みは 0 本** (全文 →
  [`bc-outer-slack-inventory.md`](bc-outer-slack-inventory.md))。**収穫ライン達成済** = 対応表 + 捨て項の
  4 種分類。**残る (ii) J-bound 自体の最適性** (Li 曰く "optimality unknown") **は層 3 ゆえスコープ外**で
  次 relay の最有力候補 (`outer-region-j-def`)。

### 軸 C — 情報不等式 (優先度 1。**L10 で唯一の生存経路 R2 を供給した**)

- **狙い (L10 で確定)**: 標的は **[GJNW13] Theorem 1 の `|X| ≥ 3` への正しい一般化**。**原典 §V が逐語で
  open と宣言している問い**そのもので (facts C5)、`|X| = 2` 方向は原典が閉じている (facts C1/C7)。
- **優位**: 情報不等式は有限の変数と有限の項からなるので、**Lean での検証と数値での反証の両方が効く**
  数少ない領域 (L10 の実測 = 候補 3 本のうち 2 本を明示 witness の直接評価だけで kill)。
- **⚠ 昇格根拠 (b) は原典に否定された**: 「idea `shannon-cone-lp` (elemental Shannon 不等式の LP = ITIP)
  が novelty gate を機械化する」は成り立たない — [GJNW13] §I-B-2 逐語 "this is an example of an
  inequality that cannot be deduced by even the knowledge of `Γ*₅`. This is primarily due to the
  cardinality constraint imposed on one of the random variables" (facts C4) ⟹ **`|X|` 制約つきの候補は
  必ず「Shannon 型でない」を返す = kill 枝が構造的に沈黙する** ⟹ **gate の射程を「濃度制約を持たない
  候補にのみ効く」に限定して idea 枠に残す** (殺しはしない)。
- **収穫ライン (L13 で更新)**: 経路 **R2** + probe [`bc-jognair-general-check.py`](bc-jognair-general-check.py)

### 軸 D — 特徴付けの複雑さ階層 (優先度 2、主語を差し替え)

- **狙い**: 旧狙い「単一文字特徴付けを持つ、を形式的に述べる」は **F7 で肯定的に決着済** ⟹ 主語を Li

  いない ⟹ 「どのレベルの論理式で書けるか」を問う主語として正しい形を既に持つ。
- **最初の一手 `multiletter-subject`** (⚠ **L14 で枠を落とし、L18 の拾い上げ候補へ**): (1) multi-letter

### 軸 E — 自己テンソル化 (優先度 1 → 3 (L2) → **経路の供給源としては閉じた** (L9))

- **狙い**: 未解決問題を「**Marton 領域の support function が同一チャネルのテンソル冪に対して
  自己加法的か**」という単一の命題に等価変形する (外部ノート
  [`bc-external-note-tensorization.md`](bc-external-note-tensorization.md) の同値条件 (3))。
- **⚠ 還元も、還元の全段も我々の新規性ではない** (Additivity Conjecture = [AGN19] 2019 / [GLN25]
  Conjecture 1 が同じ還元を持つ)。新規性を置けた 3 箇所は (i) 否定側インスタンス (11) → **L2 で失効**
  (保証された偽陽性)、(ii) support function 版と双対汎関数版の同値性 → **L8 で消えた** ([GLN25] 式 (1) は
  `≤` ではなく **`=`**)、(iii) → 独立軸の軸 G。
- **⟹ 残る口は 1 つで、それは経路にならない**: [AGN19] が Lemma 2 のインスタンス探索の独立再現を逐語で
  公開要請しており探索空間も指定済 (routes.md P3)。⚠ **新しい問いではない** ⟹ §3.1 の条件 (5) を

- **前提工事 `marton-3aux-probe` は見積りが下がった**が**枠は条件つき**で、価値は**軸 G に全額移った**
  (判断ログ 16 / 28)。**収穫ラインは達成済** — multi-letter 表現の正確な形 + 負の判定行の射程が閉凸包
  まで拡大 + **`U₀` 無しの時分割への潰れは `|X| = 2` 固有** (⚠ `U₀` が不要とは言っていない)。probe 2 本。

### 軸 F — 補助変数の濃度境界 (優先度 4 → **3**、L1 で主語を差し替え)

- **狙い (L1 で差し替え)**: 旧狙い「cardinality bound の改善」は層 3 ⟹ **濃度限界がどの主張の生死を
  分けるか**の仕分けへ。L1 (b) で `|U|+|V| ≤ |X|+1` を課すか否かが**同一の点について「局所最大である /
  でない」を反転させる**と分かった。`F(T,{a_x})` の定義自体には濃度制約が無いので、**制約つきと制約なしは
  同じ最適化問題ではない** — 文献の主張を引くたびにどちらの空間の話かを確認する。
- **最初の一手**: `cardinality-localmax-boundary` — Marton 領域まわりの主張を濃度制約の内側/外側で仕分け。
  ⚠ **L10 / L12 で本軸の重要度が 2 度上がった** — 濃度制約は `Γ*ₙ` の外に出るので LP gate が効かず
  (facts C4)、[N10] Definition 1 の判定可能性も濃度上界の有無で決まる (`eln-canonical-class`)。
- **⚠ 昇格の根拠は観測 1 件**なので優先度 1 相当の歩留まりを主張する材料ではない。L1 の進捗は**軸 G に
  計上し本軸には計上しない** (台帳の二重計上の注意)。

### 軸 G — Marton 領域の最適化子の構造 = Markovity 予想 (優先度 1、`parked`)

**独立軸にする理由**: 標的が単一文字・単一チャネル上の**最適化子の構造**で、軸 E (テンソル冪の加法性) とも
軸 A (等号定理の最弱仮説) とも主語が違う。**残る軸の中で §3.1 の条件 (5) を満たしうる標的を持つのはここ
だけ** — 本丸より遥かに小さく、かつ真に未解決だから。

- **狙い**: Gohari–Liu–Nair (ISIT 2025) の **Conjecture 2 (Markovity Conjecture)** — 「Marton の達成領域の
  極点を評価するときは Markov 連鎖 `U → (W,X) → V` を持つ組だけを考えれば十分」。**未解決**で、しかも
  提案の根拠は**数値証拠のみ** (`|X| = 3,4,5` で各 10,000 チャネル超)。
- **優位**: (a) Marton 領域が機械検証された `def` で在庫にある、(b) 数値 probe 基盤が L1 で建った、
  (c) 同論文 §III-B に明示された数値インスタンスが**既知の答えがある再現課題**になる (L1 で実施済)。
- **⚠ 「潰れている路線」は L1 で弱まった** — §III-B のインスタンスは**論文が §III で自ら定義する意味では
  局所最大ではない** (条件 (7)/(8) を違反)。ただし**「開いている」は推論**で、濃度限界の内側では真の
  局所最大 ⟹ **開きうるのは濃度非制約の空間に限る** (軸 F と連動)。
- **これまでの一手**: (1) ✅ L1 — §III-B のインスタンスを数値再現 (8 桁全桁一致)。(2) ✅ **L5 = 「述べ
  られるが偽」** — Conjecture 2 の「Equivalently」側を我々の support function へ移した命題 **M2 は数値
  反例で FALSE**。⚠ **Conjecture 2 の反例ではない** (`F` に残る `W` 由来の項は線形項で相殺できない)。
- **⚠ 続行には前提工事が要る (L5)**: 2 補助変数の在庫の上では行き止まりで `marton-3aux-probe` が挟まる。
  ただし L1 の harness が既に `F` を逐語実装しており、L8 が繋ぎの段を文献の定理と確定させたので、残るのは
  **文献の段を我々の `def` の上で使える形に写すこと**だけ (`markovity-via-dual-F`)。
- **⚠ 本軸は「経路を生みうる唯一の park 対象」**: 工事 1 + 構築/probe 2 = **3 leg** ゆえ発動は条件つき。
  **L14 で条件 (生存 1 本以下) は満たされたが、発動そのものは L15 の結果に条件づけて L16–L18 へ後置した**
  (判断ログ 16 / 28、§6.2)。**発動しなければ park のまま relay を終える**。
- **⚠ 知見の横流しはできない (L7 の走査)**: L5 の反例チャネル `CEX-1` は L7 のギャップも出すが、
  **§III-B のチャネルは L7 では潰れる** ⟹ 「非矩形最適点が立つ構造」と「時分割を破る構造」は**一致
  しない** (候補チャネル選定に `markovity-localopt-route` の統計を使えない)。
- **収穫ラインは達成済**: L1 の数値再現 / **M2 の反例インスタンス**と「最適点が非 Markov ⟺ 非
  rectangular」の対応 / 大域最適化 harness 2 本。

## 5. 運用規約 — 「諦めない」を仕組みで担保する

諦めが起きるのは (i) 進捗の実感が無い (ii) 何を試したか忘れる (iii) 同じ失敗を繰り返す、の 3 つ。以下は
それぞれへの構造的対処で、**すべての leg のブリーフに本節への参照を入れる**。

1. **no empty leg — 進捗の単位は「証明の完成」ではなく「確定事実 1 行」**
   各 leg は attack ledger または `bc-facts.md` に**最低 1 行の新しい確定事実を追加して終わる**。
   反証も、死因の特定も、「この route は既知だった」も、すべて確定事実。証明の完成だけを進捗と
   定義すると、未解決問題では 10 leg 連続でゼロ進捗になり、そこで必ず諦めが起きる。

2. **kill-first — 反証ファースト**
   候補命題を立てたら、**まず数値 probe で殺しにいく**。証明に投資するのは殺せなかった命題だけ。
   `bc-marton-union-gap-check.py` が先例で、実際に 1 本の逆包含を殺して路線変更を導いた。**道具は
   L1 で `bc_probe.py` として汎用化済** (載せ方は §2.1) なので、本規約はもう空文ではない。
   これは時間の最大の節約であると同時に、自己欺瞞に対する最大の防波堤。

3. **proof-probe — 核だけ先に機械検証** (§2.1 層 2): 散文が完成する前に核 1〜2 ステップを検証する。

4. **attack ledger — 探索木の永続化**
   1 attack = 1 行。列 = slug / 軸 / 状態 (`live` / `killed` / `parked` / `harvested`) / **死因**
   (`numeric-counterexample` / `known-result` / `probe-failed` / `too-hard` / `mathlib-wall`) /
   残った副産物 / 最終更新 leg。`killed` の行は**削除しない** (plan hygiene の「決着済は削除」の例外 —
   ここでは死因そのものが資産)。

5. **round-robin — 軸の強制切替**
   1 つの軸で **3 leg 連続で確定事実がゼロ**なら、その軸を `parked` にして別の軸へ移る。同じ思考
   パターンの周回を構造的に止める。park した軸は 3 leg 後に再検討可 (新しい確定事実が入っていれば)。

6. **harvest line — 撤退ラインではなく収穫ライン**
   通常の撤退ラインは「詰んだら諦める」だが、未解決問題では**詰んだときに何を収穫して撤退するか**を
   事前に書く (§4 の各軸 (d))。これがあると「失敗」が「別の成果」に変わり、諦めではなく移動になる。

7. **novelty gate — 新規性主張の前に文献確認**
   「未知の結果を得た」と書く前に、必ず文献確認を 1 手挟む (WebSearch + 該当論文の verbatim 確認)。
   既知結果の再発見を新規と誤認するのは、長期セッションで最も起きやすく最も高くつく事故。
   ⚠ 逆向きの事故もある — **「既知だろう」で切り捨てる**。in-repo 資産の見落としと同じ構造 (CLAUDE.md
   「Search in-project before concluding 絶対」)。既知判定にも出典を要求する。

8. **anti-self-deception — 散文にも honesty doctrine**
   CLAUDE.md の Lean 側 doctrine を散文へ移植する:
   - 散文の各補題に「その仮説は precondition か load-bearing か」のラベルを付ける。
     **核を仮説に押し込んだ散文証明は、Lean の hypothesis bundling と同じ defect**。
   - 「〜は明らかに成り立つ」「同様にして」は**その場で層 2 の probe 対象**として台帳に起票する。
     散文における `sorry` はこの 2 つの言い回しの形で現れる。
   - 数値実験で FALSE を判定するときは、sim を実 `def` と逐語照合してから。

9. **死因は必ず子 attack を 1 本生む — ネタ切れ防止の主機構**
   attack が `killed` になったら、**その死因から新しい attack を 1 本起票してから** leg を閉じる
   (「この不等式が緩くて死んだ」→「では緩みの発生源はどのステップか」)。長期 relay で諦めが起きる
   実体は意志の問題ではなく**次に試すことのリストが空になること**なので、台帳が枯れない構造を
   規約で担保する。子を思いつかない死因だけが `harvested` に落ちる。

10. **判定は機械に寄せる — 自己評価を信用しない**
    「進捗があった / この道は生きている」を主観で判定しない。判定を次の 4 つの機械的シグナルに
    寄せる: Lean が通ったか / 数値 probe が反例を出したか / 文献に該当が有ったか / 台帳に新しい行が
    増えたか。どれにも該当しない leg は**ゼロ進捗として記録する** (§5-5 のカウントが進む)。
    ゼロ進捗を認める勇気がラウンドロビンを機能させる。

11. **primary-source-first — 一次文献を先に取る** (§5-7 の重複ではなく**補完**)
    §5-7 が定めるのは「新規性主張の前に文献確認を 1 手挟む」という**タイミング**だけで、**どの文書を
    読むか**を定めていない。L2 / L7 の 2 つの誤判定は**どちらも §5-7 の字面を守った上で発生した**。
    - **発動条件**: ある主張に `known` / `new` のラベルを付ける前に、**その主張の出所として引かれている
      参考文献のうち一次文献を 1 本は取得する**。⚠ 二次文献が「[n] による」と書いている段を**二次文献の
      逐語で判定しない** (実例 2 件はどちらも原典 1 本で解消し、**二次文献の側が式を粗く書いていた**)。
    - **取得経路**: 一般検索より先に**著者の publications ページ**を当たる (⚠ ディレクトリ一覧が 403 でも
      個別 PDF は取れる)。**⚠ 実測による訂正 3 点**: (a) **ファイル名を推測せず一覧を 1 回取って `href` を
      抜く** (推測 9 通りは全部 404 だが `publications.html` は 200 で全 PDF リンクを持つ)、(b) **会議版と
      掲載版があるなら掲載版を優先する** ([NWG10] の heuristic な段を上位版 [GJNW13] が反例つきで断定 =
      **同じ論文の版差が判定を分けた実例**、facts C4)、(c) **表題語で探索を切ると標的を正面から扱う論文を
      落とす** (facts C8 の訂正 = arXiv:1202.0898 は表題に濃度が出ない)。
    - **取得できないとき**: 「二次文献のみで判定した」と**明示的にラベルする** ([`bc-facts.md`](bc-facts.md)
      の confidence は `human-judgment` のまま `(primary)` / `(secondary)` の但し書き。§6.6)。

12. **generic-instance-first — 記録済の必要条件を全部通しても候補は死ぬ** (L13 で追加、§5-2 の精密化)
    旧規約 (L10) の「必要条件は片方ずつでなく**全部**に当ててから probe する」は**必要だが十分でない**
    — L13 の候補 3 本のうち 2 本は **(N1)(N2) を両方通したうえで generic に死んだ**。原因は構造的で、
    **記録済の必要条件は witness から抽出されるぶん、その witness が立つ*退化点*に張り付く**
    (ここでは `|X|=2` と決定論的 BC で、ちょうど kill 機構が相殺する 2 点だった) ⟹ **全通過は
    「退化点で正しい」ことしか意味しない**。⟹ **構築の前に 2 つ足す**: (a) **3 本目の必要条件 =
    「非決定論的チャネルでの局所最適性」** (L13 の死んだ 2 案はちょうどこれで落ちる)、(b) **generic な
    非退化インスタンス 1 本** (dense = 全遷移確率 > 0 / 非決定論的 / `|X| ≥ 3` / 非一様 `p(x)`)。
    ⚠ **付随する測定規律**: **最適化器の非違反行は弱い証拠** (L13 の 1 run だけで偽陰性 3 件、L10 と
    合わせて 4 件目) ⟹ 決着は**明示 witness 族の直接評価**で付け、**統計は「率」ではなく「探索強度に
    依存する下界」と書く**。

13. **provable-first — 「証明できる下界」から作ると必要条件が*測定*に変わる** (L15 で追加、§5-12 の後続)
    L13 の 3 候補は**未証明の主張**だったので、必要条件を全部通しても generic な反例で死んだ。L15 は
    順序を逆にし、**先に証明できる不等式を作ってから (N1)(N2) を当てた** — すると (i) 反例では死なない
    (第 3 の必要条件 §5-12 は**自動で満たされる**)、(ii) 必要条件は「殺すテスト」ではなく**鋭さの測定**
    になり、不合格でも**候補ではなく設計指針が更新される**。実際 L15 では「(N1) を満たす `Λ` は
    [GJNW13] Theorem 1 を*含意する*」が読み取れ、**「必要条件が既発表の定理そのものなら、緩和で再現を
    期待せず base case として*内蔵*せよ」**という指針になった (それが R3 の分割再帰である)。
    ⚠ **符号の非対称性を先に決めておく**: 推定量が真値の下界か上界かを決めておくと、**片側の測定値だけが
    証明書になる** (L15: `Gamma` は最大化 = 下界 ⟹ `Λ` は上振れ ⟹ **正の deficit だけが証明書、負は
    最適化ノイズ**)。⚠ **証明済の量でも「推定不足」は起きる** — 下界の*推定*が既知の真値を超えたら、
    それは反例ではなく計算の不足なので、**黙って除外せず「推定不足」として分けて数える**
    (L15 §2 の `|X|=9` が実例)。

## 6. イテレーションの設計

**予算 = 20 leg** (超過時に延長するかは 20 leg 完了時点で判断)。

### 6.1 1 leg の内部構造

leg は毎回この形。中身の attack が何であれ枠は変えない。

| 段 | やること | 所要 |
|---|---|---|
