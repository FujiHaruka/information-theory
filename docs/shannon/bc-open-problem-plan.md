## 2. Approach

**三層 × 階段 × 台帳**。

### 2.1 三層 — ただし**この relay のゴールは層 1〜2 まで**

```
層 1  散文        アイデア + 証明スケッチ (自然言語 + 数式)        ← 本 relay のゴール
層 2  proof-probe 核 1〜2 ステップだけを機械検証 (数値 sim or Lean)  ← 本 relay の検証手段
層 3  形式化      散文全体を Lean へ                              ← ⚠ 本 relay のスコープ外
```

**層 3 は次の relay に回す**。理由は単純で、**散文レベルの証明がまだ存在しない**から。形式化は「正しい
散文があること」を前提にした作業なので、前提が無い段階で形式化に予算を割くのは順序が逆になる。
したがって本 relay の成果は「**probe を通過した候補経路が数本**」であり、それらが**誤っている可能性は
織り込む** — 誤りの排除は層 3 の仕事であって、ここでの目的ではない。

**層 2 の役割はそれに合わせて変わる**。形式化への入口ではなく、**散文の自己欺瞞を最短で殺す装置**。
未解決問題における最大のリスクは「散文で証明できた気がする」であり、これを 1 leg 以内に潰せるかが
探索速度をそのまま決める。層 2 は「その散文が核として何を要求しているか」を機械に問い合わせ、
**通れば核が生き / 通らなければ壊れている場所が特定される**のどちらかを必ず返す。

層 2 の 2 形態と使い分け:

- **数値 probe (主力)** — 命題を有限アルファベットの数値最適化に落として反例を探す。層 3 を捨てた
  以上、検証の主力はこちら。**基盤は L1 で完成した [`bc_probe.py`](bc_probe.py)** (自己検証 =
  `python3 docs/shannon/bc_probe.py`)。新しい命題を載せる口は 3 つで、命題の形で選ぶ:
  - **線形情報量式** (恒等式 / 不等式) → `parse("I(A;Y1) + I(B;Z2) - I(A;B)")` で文字列のまま書き、
    まず `prove_identity` で**係数相殺 = 証明**を試みる。落ちたら `test_relation(..., rel="<=")` で掃引。
    **掃引の成立は証拠、係数相殺は証明** — 台帳にはこの区別を書き分ける。
  - **構造制約** (独立性 / Markov 連鎖 / 決定論的符号器 / メモリレス性) → `BayesNet` に DAG として
    置く (無制約なら `random_joint`)。⚠ 一般 BC は `Y ⊥ Z ∣ X` を仮定できないので `(Y,Z)` は
    **結合 1 ノード**にする (積 BC で置くと射程が狭まる)。
  - **補助変数上の最大化** → `maximize` (多点再スタート、返るのは最良値であって最大値の証明ではない)
    + `local_max_certificate` (摂動族 `pε = (1−ε)p + εs` に対する局所最大性)。⚠ **ランダム方向の
    摂動だけで「局所最大だ」と結論しない** — L1 で実際に、改善方向が単体の**境界** (決定論的な `q`) に
    あってランダム 20,000 方向が全滅した事例が出た。`directions=` に境界点を明示的に渡す。

  実行可能な probe は `bc-*-check.py` として別ファイルに置き、本 module を import する。
  **sim は必ず Lean の `def` と逐語照合してから信用する** (CLAUDE.md 検証の誠実性) — ただし
  `bc_probe.py` 自体は InformationTheory の `def` に依存しないので、照合義務は**その `def` を扱う
  consumer 側の probe が負う**。基盤が負う照合は entropy の規約 (自然対数版) 1 点のみで、これは済。
- **Lean probe (安いときだけ)** — **既存資産に問い合わせるだけで済む場合に限る**。典型は軸 A の
  「仮説を差し替えて再コンパイル」— 数行の編集で機械が答えを返す。新しい補題を積む必要が出た時点で
  それは層 3 の作業なので、**打ち切って散文に戻る**。

### 2.2 階段 — 本丸に直行しない

未解決本体だけを目標にすると「解けない = 成果ゼロ」になり、それが諦めの唯一最大の原因になる。
**どこで止まっても成果が残る**よう、独立に価値を持つ 4 段に割る (§3)。

### 2.3 台帳 — 失敗を資産に変える

試した attack は死んだものも全部 attack ledger に残す。**死因の分類**まで書くのが要点で、「数値反例で
死んだ」「既知だった」「単に難しい」は次の一手が全く違う。台帳がないと長期 relay は同じ壁に何度も
当たり、そこで「もう無理だ」という誤った確信が生まれる。

## 3. ターゲットの階段

**完了条件はすべて散文ベース** (層 3 はスコープ外、§2.1)。

| 段 | 内容 | 完了条件 | 価値 |
|---|---|---|---|
| **T0** | ギャップの正確な固定 | 内界・外界・容量領域が同じ言語で並び、「何が未解決か」が曖昧語なしで書ける | 在庫でほぼ達成済 |
| **T1** | **既知の負の結果**の再現 | F4 (BSSC のギャップ) / F5 (NEG の suboptimality) の証明の**筋が追えていて、どの道具が効いたかが言える** | 道具立てがここで揃う。新規性は無いが、以後の全 attack の入力 |
| **T2** | **人類未知の中間結果の候補経路** ← 本命 | §4 の軸のいずれかで、§3.1 の 5 条件を満たす経路が立つ | 次 relay の形式化対象。ここが現実的な到達目標 |
| **T3** | 未解決本体の候補経路 | 一般 BC の計算可能な特徴付け (肯定 or 否定) について同じく経路が立つ | 30 年級。狙うが期待値は置かない |

### 3.1 「候補経路」と呼べるための 5 条件

**これを満たすものだけを経路 (route) として台帳に載せる**。満たさないものは `idea` 枠に置く
(アイデアは自由に量産してよい — 制約をかけるのは経路への昇格時だけ)。基準が無いと
「経路が 5 本出た」が空虚な数字になる。

1. **主張が確定している** — 何を証明する経路なのかが 1 文で書け、その命題に曖昧語 (「適切な」
   「よい性質の」) が無い
2. **ステップが列挙されている** — 中間命題の列があり、各ステップの入力と出力が書かれている
3. **各ステップにラベルが付いている** — `known` (既知の道具で行ける、出典つき) / `new` (新規に証明が
   要る) / `gap` (未検討)。**`gap` が残っていてもよい** — 隠さずに書いてあることが条件
4. **殺されていない** — 主張自体の小ケースを数値 probe に 1 回は通した
5. **既知でない** — 文献確認を 1 回通した (§5-7)

### 3.2 経路の確信度ラベル

| ラベル | 意味 |
|---|---|
| `probed` | 核ステップが数値 or Lean で検証を通過した |
| `unprobed` | 散文のみ。probe 未実施 |
| `refuted` | 殺された (死因を台帳へ) |

**`unprobed` のまま「証明できた」と書かない**。誤りを織り込むこと (§2.1) と、誤りを誤りと表示しない
ことは別。層 3 を捨てた代償はこのラベルで払う。

### 3.3 本 relay の到達目標 (L14 の収穫判定で使う)

- **最低ライン**: 5 条件を満たす経路 ≥ **2 本**、うち ≥ **1 本**が `probed`
- **目標**: 経路 ≥ **3 本**、うち ≥ **2 本**が `probed`
- 経路の本数は多いほど良いわけではない。**次 relay で形式化に着手できる粒度**まで書けているかが基準。
- **現在地 (L8 完了時点) = 有効な経路 0 本**。R1 は (4) probe を通ったが **(5) novelty gate で不合格**
  ⟹ 最低ライン (経路 ≥ 2 本 / うち `probed` ≥ 1 本) は依然未達で、**L7 の 1 本が消えた分だけ後退した**。
  ⚠ **本数の現物は台帳から再導出する** (5 条件を満たすまで経路表に載らない。plan にキャッシュしない)。

## 4. 攻撃軸 — 未知の中間結果の候補

各軸に (a) 狙い / (b) 形式化プロジェクトゆえの優位 / (c) 最初の一手 / (d) 収穫ライン (死んだときに残るもの)
を書く。**単一の軸に賭けない** — §5-5 のラウンドロビン規約で強制的に回す。

### 軸 A — 在庫駆動の最弱仮説抽出 (優先度 1)

- **狙い**: 既に証明済の等号定理が**実際に使っている仮説**を最小化し、既知クラスより真に広いクラスを
  切り出す。親 plan の記録によれば `bc_moreCapable_uv_subset_superposition` の「唯一の新しい数学の核」は
  `IsBCMoreCapable.condMutualInfo_le` 1 本 = **証明はクラス定義そのものではなくその帰結 1 本しか
  使っていない可能性が高い**。ならばその帰結を定義に採ったクラスで同じ等号が成立する。
- **優位**: 「証明が本当は何を使ったか」は散文の論文からは読めない。**Lean は仮説を差し替えて
  `lake env lean` に問える** — これは形式化プロジェクトだけが持つ発見手段。⚠ **手順の訂正 (L3)**:
  実使用の棚卸しは証明本文の `rg` ではなく **`dep_graph.sh` の前方閉包**で行い、**辺の向き先が `def`
  自身か名前つき補題か**を区別する (`rg` では `exact hmc _` 形の `def` 直接展開が構造的に見えない)。
- **最初の一手 — L3 で実行、判定 FAIL**: `IsBCMoreCapable` を `condMutualInfo_le` の結論に差し替えると
  **通らず** (足りないのは `def` 本体 1 本のみ)、しかも**両方向を機械検証すると差し替え先は元クラスと
  同値** ⟹ **新クラス候補ゼロ**。狙いにある「帰結 1 本しか使っていない可能性が高い」は**誤りだった**
  (逐語 → [`bc-facts.md`](bc-facts.md) §機械検証 probe の判定 (L3))。
- **収穫ラインは達成済、ただし形が変わった** — 残るのは**この同値そのもの**。⚠ 平均化による古典的同値で
  **新規性はない** (新しいのは我々の `def` の上で機械検証されたことだけ)。
- **⚠ 軸自体は生存 (優先度 1 据え置き)**: 死因から子 attack 2 本 — `weakest-hyp-degraded-lessnoisy`
  (⚠ 同じ同値で潰れる公算も高い) と `class-def-vs-consequence-gap` (**条件つき版と非条件版が同値に

## 5. 運用規約 — 「諦めない」を仕組みで担保する

諦めが起きるのは (i) 進捗の実感が無い (ii) 何を試したか忘れる (iii) 同じ失敗を繰り返す、の 3 つ。
以下はそれぞれへの構造的対処で、**すべての leg のブリーフに本節への参照を入れる**。

1. **no empty leg — 進捗の単位は「証明の完成」ではなく「確定事実 1 行」**
   各 leg は attack ledger または `bc-facts.md` に**最低 1 行の新しい確定事実を追加して終わる**。
   反証も、死因の特定も、「この route は既知だった」も、すべて確定事実。証明の完成だけを進捗と
   定義すると、未解決問題では 10 leg 連続でゼロ進捗になり、そこで必ず諦めが起きる。

2. **kill-first — 反証ファースト**
   候補命題を立てたら、**まず数値 probe で殺しにいく**。証明に投資するのは殺せなかった命題だけ。
   `bc-marton-union-gap-check.py` が先例で、実際に 1 本の逆包含を殺して路線変更を導いた。**道具は
   L1 で `bc_probe.py` として汎用化済** (載せ方は §2.1) なので、本規約はもう空文ではない。
   これは時間の最大の節約であると同時に、自己欺瞞に対する最大の防波堤。

3. **proof-probe — 核だけ先に機械検証** (§2.1 層 2): 散文が完成する前に核 1〜2 ステップを検証する。

4. **attack ledger — 探索木の永続化**
   1 attack = 1 行。列 = slug / 軸 / 状態 (`live` / `killed` / `parked` / `harvested`) / **死因**
   (`numeric-counterexample` / `known-result` / `probe-failed` / `too-hard` / `mathlib-wall`) /
   残った副産物 / 最終更新 leg。`killed` の行は**削除しない** (plan hygiene の「決着済は削除」の例外 —
   ここでは死因そのものが資産)。

5. **round-robin — 軸の強制切替**
   1 つの軸で **3 leg 連続で確定事実がゼロ**なら、その軸を `parked` にして別の軸へ移る。同じ思考
   パターンの周回を構造的に止める。park した軸は 3 leg 後に再検討可 (新しい確定事実が入っていれば)。

6. **harvest line — 撤退ラインではなく収穫ライン**
   通常の撤退ラインは「詰んだら諦める」だが、未解決問題では**詰んだときに何を収穫して撤退するか**を
   事前に書く (§4 の各軸 (d))。これがあると「失敗」が「別の成果」に変わり、諦めではなく移動になる。

7. **novelty gate — 新規性主張の前に文献確認**
   「未知の結果を得た」と書く前に、必ず文献確認を 1 手挟む (WebSearch + 該当論文の verbatim 確認)。
   既知結果の再発見を新規と誤認するのは、長期セッションで最も起きやすく最も高くつく事故。
   ⚠ 逆向きの事故もある — **「既知だろう」で切り捨てる**。in-repo 資産の見落としと同じ構造 (CLAUDE.md
   「Search in-project before concluding 絶対」)。既知判定にも出典を要求する。

8. **anti-self-deception — 散文にも honesty doctrine**
   CLAUDE.md の Lean 側 doctrine を散文へ移植する:
   - 散文の各補題に「その仮説は precondition か load-bearing か」のラベルを付ける。
     **核を仮説に押し込んだ散文証明は、Lean の hypothesis bundling と同じ defect**。
   - 「〜は明らかに成り立つ」「同様にして」は**その場で層 2 の probe 対象**として台帳に起票する。
     散文における `sorry` はこの 2 つの言い回しの形で現れる。
   - 数値実験で FALSE を判定するときは、sim を実 `def` と逐語照合してから。

9. **死因は必ず子 attack を 1 本生む — ネタ切れ防止の主機構**
   attack が `killed` になったら、**その死因から新しい attack を 1 本起票してから** leg を閉じる
   (「この不等式が緩くて死んだ」→「では緩みの発生源はどのステップか」)。長期 relay で諦めが起きる
   実体は意志の問題ではなく**次に試すことのリストが空になること**なので、台帳が枯れない構造を
   規約で担保する。子を思いつかない死因だけが `harvested` に落ちる。

10. **判定は機械に寄せる — 自己評価を信用しない**
    「進捗があった / この道は生きている」を主観で判定しない。判定を次の 4 つの機械的シグナルに
    寄せる: Lean が通ったか / 数値 probe が反例を出したか / 文献に該当が有ったか / 台帳に新しい行が
    増えたか。どれにも該当しない leg は**ゼロ進捗として記録する** (§5-5 のカウントが進む)。

### 6.3 進捗と死亡のシグナル (事前定義)

途中で気分に応じて判定しないよう、先に書いておく。

**live** (1 つでもあれば軸は生きている): Lean の仮説差し替えが通った / 複数の異なる設定で数値 probe が
反例を出せなかった / 文献に該当が無いことが確認できた / 新しい部分命題が 1 本立った。

**killed** (死因を台帳へ): 数値反例が出た (sim を実 `def` と照合済) = `numeric-counterexample` /
文献に既出 = `known-result` / probe が通らず原因が命題の偽性に帰着した = `probe-failed` /
Mathlib 側の資産が無く自作行数が見積れる = `mathlib-wall`。

**⚠ 「難しい」は死因ではない**。`too-hard` を使ってよいのは、**必要な補題を名指しでき、その自作行数を
見積れたときだけ**。名指せないなら `parked` (§5-5) であって死ではない。この区別が、悪い諦めを
構造的に止める唯一の場所。

### 6.4 詰まったときの診断 — 順序を固定する

証明が通らないとき、原因は 4 つある。**この順で潰す**。多くの時間は「4 から始める」ことで溶ける。

1. **命題が偽か?** → 小ケースを数値 probe で叩く。**未解決問題では偽の確率が通常の形式化より遥かに高い**
   ので最優先。既に inner = outer / outer = capacity の 2 本が偽と分かっている家系である。
2. **定義がずれているか?** → 我々の Lean `def` と文献の定義を verbatim 照合。特に補助変数の量化範囲、
   共通メッセージの有無、閉包の取り方。
3. **補題が足りないか?** → loogle (Mathlib) → `rg` + `dep_consumers.sh` (in-repo)。CLAUDE.md の
   二段構え。**in-repo を飛ばさない** (この家系は「2 ファイル隣に既にあった」の前科がある)。
4. **証明が見つからないだけか?** → 別戦略を 1 つ試し、駄目なら `parked`。

### 6.5 両方向の義務 — 悪い諦めと自己欺瞞に非対称に効かせる

- **「この道は死んだ」と書く前に、生きている証拠を 1 つ探す** (CLAUDE.md の壁反証義務の適用)。
- **「証明できた」「これは新しい」と書く前に、反例を 1 つと文献を 1 つ探す** (§5-2 / §5-7)。

前者が悪い諦めを止め、後者が自己欺瞞を止める。**片方だけでは必ずもう片方に倒れる**。

### 6.6 棚卸し leg (L4 / L9 / L14) にやること

探索が局所に沈むのを防ぐ定点観測。所要は 1 leg 未満でよい。

1. 台帳の全行を俯瞰し、`live` / `parked` / `killed` の分布を見る
2. **ゼロ進捗カウントが 3 に達した軸を強制 park** し、park 済みの軸に再開条件が揃ったか見る
3. **アイデアの供給源を 1 周する** — 死因からの派生 (§5-9) / 類似問題からの移植 (**MAC / Han /
   Slepian–Wolf / Wyner–Ziv が同じライブラリにある。⚠ interference channel は在庫に無い**、L4 で確認) /
   既存証明の読み直し / 数値実験のパターン / 文献の未使用の道具
4. 残り leg 数と §6.2 の配分を突き合わせ、必要なら可変枠の割り当てを変える
