## 0. ゴール — 未解決本体そのもの

**一般 2 受信者 DM-BC の容量領域の計算可能な特徴付けを、肯定側か否定側のどちらかで決着させる。
散文の証明と、その Lean による機械検証の両方をもって完了とする。**

完了条件 (どちらか一方):

- **肯定側** — 任意の `ε > 0` に対し有界時間で `ε` 近似を返す手続きを構成し、その正当性を証明する。
- **否定側** — そのような手続きが存在しないことを証明する。

いずれの側も、**散文の証明が立つこと**と**Lean で proof done に到達すること** (0 sorry / 0 residual、
`#print axioms` が sorryAx-free、かつ署名走査で load-bearing hypothesis が無いこと) の両方を満たして
初めて達成とする。片側だけでは達成ではない。

### 0.1 ⚠ ゴール保護条項 — 本節は leg / planner が書き換えてはならない

**前 relay で実際に起きた事故がこれである**。原案 (`487afc03`) は T2 の完了条件を
「文献に無い命題が **Lean で機械検証される**」と書き、§2.1 に「**ユーザー指定の二段構え
(散文で証明 → 形式化で検証)**」と明記していた。それを `28a740c5` が **L0 が走る前に**
「散文レベルの候補経路」へ書き換え、形式化をスコープ外にした。判断ログにはユーザー判断としての
記録が無い ⟹ **planner の独断でゴールが狭まり、20 leg がその狭いゴールで回った**。

したがって本 plan では以下を規約とする:

1. **§0 のゴールと完了条件を狭める変更は、leg / planner が適用してはならない**。狭める提案は
   判断ログに **`GOAL-CHANGE`** として起票し、**ユーザーの承認を得るまで適用しない**。
   広げる方向 (より強い完了条件) は起票不要。
2. **中間結果は記録するが、ゴールの代替にはしない**。台帳 (facts / attacks / routes) への収穫は

   (T0–T3) が持っていた「どこで止まっても成果が残る」というヘッジは、**記録の設計としては継承し、
   ゴールの設計からは外す** — ユーザーが「成果ゼロで終わる可能性を引き受ける」と明示的に選んだ。
3. **各 leg は冒頭に「この leg は §0 のゴールに対して何を動かすか」を 1 行で書く**。書けない leg は
   起票しない。

## 1. 標的の正確な定義 — ここを間違えると全部ずれる

**「計算可能」の語義は 2 つあり、混ぜてはならない** (facts §L12 (A4) が SoT)。

- **[N13] の語義 (本 plan の標的)** — 脚注 1 逐語: "A rate region is said to be computable if for
  every ǫ > 0, one can find a bounded time T_ǫ such that the region can be approximated to within
  ǫ in time T_ǫ." ⟹ **`ε` 近似が有界時間で可能か**。
- **Boche 系の語義 (本 plan の標的ではない)** — Banach–Mazur computability の否定。**FSC 容量 /
  DMC の最適入力分布**について確定しているが、**BC には移植されていない** (facts F8)。

**単一文字性は標的ではない**。F7 (Li 2021, Theorem 10 + Proposition 15) により BC 容量領域は
`Δ₁₈ᴴ` に入ることが確定しており、単一文字特徴付けを持つかは**肯定的に決着済**。F7 脚注 3 が
**単一文字性と計算容易性を別軸として分離**している。⟹ **前 relay が追っていた加法性 / 鋭いスラックは
T3 への必要条件ではない**。

### 1.1 標的が要求しているものの分解 (L0 で gate 済 — 穴は 1 つに縮んだ)

原案の 3 分解 (C1)(C2)(C3) は L0 の一次文献 gate で**訂正された**。判定の SoT は
[`bc-facts.md`](bc-facts.md) の `## L0 (T3)` 節 (逐語と再検証コマンドはそちらにある。ここへ複製しない)。

- **(C1) 計算可能な内界の列 — 既に在る**。正規化 n-letter Marton 内界の増加列が容量領域へ収束する
  ことは**証明済**であって予想ではなく、各 `n` の Marton 領域はカーディナリティ境界により計算可能。
  ⟹ 容量領域は **computably overt** (下から半計算可能) である。
  **領域版の逐語出典も取れた** (facts §L1(T3) 行 4)。
- **(C2) 外界側 — ここが唯一の穴。L2 で問いの形そのものが変わった**。要求は「上から収束する計算可能な
  外界**列**を作る」ことでは**ない** — **`C` を共通部分にもつ、`k` と `W` について一様に半計算可能な
  外界の可算族が 1 つでも存在するか**と同値である。**減少性も有効収束率も要らない**
  (facts §L2(T3) 行 5)。さらにそれは **基数有界かつ閉アトムの一階特徴づけが存在するか**と等しい
  (同 行 10)。⟹ 一文で言えば容量領域の **effective compactness** が未知、という記述は変わらない。
  **`Thm7(W)` (= [auxrec] Theorem 7、`∀J` 形) が `W` について一様に effectively compact であることは
  L2 で証明できた** ⟹ **(C2) ⟸ (`Thm7(W) = C(W)`)**。この還元先の最適性は一次文献が「未解決」と
  明言している (同 行 6–7)。⚠ **「未決」であって「偽」ではない**。
- **(C3) 有効収束率 — 独立の課題ではない**。計算可能解析の標準定義
  (`computable = effectively compact ∧ computably overt`) より、両側が揃えば停止則は自動的に従う。
  ⟹ **(C3) は (C2) に吸収される**。**L2 でこれはさらに強くなった** — (C2) の同値形の証明に
  収束率も減少性も一切現れない (facts §L2(T3) 行 5) ので、収束率を独立の課題として立てる余地は無い。

⟹ **本 plan の標的は 1 文で書ける** — 容量領域の **effective compactness** を示す (肯定側) か、
否定する (否定側) か。

**訂正 1 件**: [N13] の "there are computable inner bounds and outer bounds" は**固定領域**を指しており、
原案がこれを「収束する列」と読んだのは誤りである。

**難度の較正** (⚠ **我々の演繹、未 probe**): 否定側は **Marton 最適性予想の反証を含意する**
(facts §L0(T3) 行 9–10)。⟹ 原案 §3 が T3-β の根拠にしていた「BC についての一次文献が無いから
新規性は構造的に確保されている」という読みは**成立しない**。新規性ではなく**難度**の問題である。

## 2. Approach

**三層は前 relay と同じだが、層 3 がスコープ内である**。

```
層 1  散文        アイデア + 証明スケッチ
層 2  proof-probe 核 1〜2 ステップを機械検証 (数値 sim or Lean) — 散文の自己欺瞞を最短で殺す装置
層 3  形式化      散文全体を Lean へ                            ← ⚠ 本 relay ではスコープ内
```

層 2 の役割は前 relay と同じ (自己欺瞞の除去) だが、**層 3 が控えているので層 2 で止めない**。
層 1 が通ったものは層 3 に載せ、載らなければ載らない理由が層 1 の欠陥である。

**順序**: 層 1 → 層 2 → 層 3 を命題単位で回す。全体が揃うのを待って形式化を始めない
(前 relay の「散文が無いから形式化は前提を欠く」は正しいが、それは**命題ごとの順序**であって
**relay 全体の順序ではない**。この取り違えがゴール縮小の理由づけに使われた)。

**⚠ 層 2 の道具が前 relay から変わる**。前 relay の層 2 は数値掃引 (`bc_probe.py` 系) だったが、
T3 の主語は計算可能性なので**数値掃引は原理的に効かない** (有限の掃引は「有界時間で `ε` 近似できるか」を
判定できない)。⟹ 層 2 は**小さな命題の厳密証明と反例構成**が中心になり、層 1 と層 3 の距離が縮む =
**命題単位で層 3 へ載せる運用が前 relay より早く回る**。

### 3.1 ⚠ 使えないと分かっているもの (前 relay の確定事実。再探索しない)

- **内界 = 外界の路線は死んでいる** (F4: BSSC で sum rate にギャップ `≈ 0.0109`)。
- **外界 = 容量の路線も死んでいる** (F5: 逆向き semi-deterministic の積 BC で UV は strictly
  suboptimal、ギャップ `≥ 4/15`。共通メッセージ版 UVW も同時に死ぬ)。
- **内界 = 容量は死んでいない** (F2: 未解決の予想)。正しければ最低レベルは `Σ₁ᴴ` (T3-γ と直結)。
- **軸 A / 軸 B / 軸 E は経路の供給源として閉じている** (前 plan §4)。
- **`{Z}` の閉包演算だけで作る支配チャネル族は利得が定義から 0** (facts §L18、4 行の証明)。
- **停止則 (有効収束率) を内界列・外界列と独立した課題として立てる路線は死んでいる** — 計算可能解析の
  標準定義から自動的に従うため (facts §L0(T3) 行 5)。
- **[Li21] の階層のレベルを下げる路線は T3 に効かない** — Li 自身が計算容易性との無関係を明記している
  (facts §L0(T3) 行 6)。
- **UV 外界を多文字化して縮める路線は死んでいる** — `∩_n (1/n)UV(W^⊗n) = UV(W)` で改善はゼロ
  (facts §L1(T3) 行 1)。
- **`∃` 形外界を多文字化して縮める路線は一般に死んでいる** — 十分条件 (H1)–(H5) の下で
  `∩_n (1/n)O(W^⊗n) = O(W)` (facts §L2(T3) 行 9)。UV は**その特別な場合**であり、反例 2 種
  (`max` を含む形 / 基数境界を領域の定義に書き込む形) が適用範囲の境界を画定している。
  ⚠ **射程の限定 (これを落とすと後の leg が誤って探索空間を狭める)**: 死んでいるのは「多文字化」という
  **1 つの機構だけ**であり、`∃` 形外界の**別の可算族**が上から `C` に収束する可能性は一切排除されない。
  ⚠ 符号に注意 — 同じ優加法性は**内界では逆に働く** (多文字 Marton が単文字より真に大きいことと整合)。
